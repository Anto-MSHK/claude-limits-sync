# claude-limits-sync

Общий учёт лимитов (неделя и 5 часов) между любым числом машин плюс Telegram-бот.
Пулы лимитов считаются независимо: `claude` (подписка Claude) и `zai` (Z.ai GLM Coding Plan).
Машины и их имена общие для всех пулов: имя задаётся в боте (`/rename`), цвет одинаковый везде.

```
 Mac: статус-лайн ──┐                         ┌── Telegram-бот (/limits, /history, /settings)
                    ├─► Cloudflare Worker ────┤
 Win: статус-лайн ──┘   (Durable Object)      └── cron раз в 10 мин → напоминания перед сбросом
```

## Как считается доля машины

Лимит общий на аккаунт, поэтому общий % (`rate_limits.*.used_percentage`) видят все машины одинаковым.
Зато каждая машина точно знает свои траты: `cost.total_cost_usd` по сессиям.

1. Клиент шлёт на сервер `{общий %, resets_at, session_id, стоимость сессии}`.
2. Сервер копит, сколько $ потратила каждая машина с последнего изменения общего %.
3. Когда общий % вырос на Δ, Δ делится между машинами пропорционально их тратам за этот промежуток.
4. Если прирост есть, а трат никто не прислал, он ждёт 10 минут (вдруг отчёт другой машины ещё в пути).
   Если трат так и не будет, прирост уходит в **web / телефон**: claude.ai, мобильное приложение и всё,
   что не шлёт отчёты.
5. Что было потрачено до запуска синхронизации, видно как **«до синхронизации»**. Клиент один раз
   отправляет старую локальную оценку из `~/.claude/limit-split.json`, и сервер переносит эту часть на машину.

Отчёт уходит при каждом изменении процентов и не чаще раза в 5 с, если менялась только стоимость.
Сеть статус-лайн не ждёт: полоска рисуется из кеша последнего ответа сервера.

## Развёртывание сервера (один раз)

```bash
cd worker
npm install
npx wrangler login                     # вход в Cloudflare (откроется браузер)
npx wrangler secret put API_TOKEN      # придумай длинный токен: openssl rand -hex 24
npx wrangler secret put BOT_TOKEN      # токен от @BotFather
npx wrangler deploy                    # выведет URL вида https://claude-limits.<you>.workers.dev
curl -X POST https://claude-limits.<you>.workers.dev/setup -H "Authorization: Bearer <API_TOKEN>"
```

Потом напиши боту в Telegram: `/start <API_TOKEN>`. После этого бот отвечает только тебе.

## Установка клиента (на каждой машине)

```bash
bash client/install.sh https://claude-limits.<you>.workers.dev <API_TOKEN> [id]   # id по умолчанию — имя компьютера
```

Затем в `~/.claude/statusline-command.sh` перед блоком «7-day limit» добавь вызов клиента
(установщик покажет нужные строки). На Windows понадобится Git Bash и `jq` (`winget install jqlang.jq`).

Статус-лайн:

```
7д ███████████▒░░░░░░░░ Работа 31% Дом 22% web 2% своб 45% ~1д5ч
   цвета машин как в боте (🟦 🟧 🟩 🟨 🟫), своя — жирным; фиолетовый — web, серый — «ранее», ▒ — ещё распределяется
   состав участников, имена и цвета приходят с сервера — в клиенте ничего не захардкожено
```

`⚠sync` значит, что последний отчёт не дошёл до сервера.

## Z.ai

Статус-лайн Z.ai (`~/.claude-zai/statusline-command.sh`) сам получает квоту из `api.z.ai/.../quota/limit`.
Из неё собирается вход в формате статус-лайна Claude и передаётся тому же клиенту с `LIMITS_POOL=zai`:

- проценты окон: `currentValue / usage` (кредиты, дробные — делятся точнее, чем у Claude);
- «вес трат» сессии: `cost.total_cost_usd`, а если Claude Code не считает стоимость для GLM — токены сессии
  (одинаковая модель на всех машинах → пропорция верная);
- старую оценку `.device-week-counter.json` как baseline не шлём: она записывает на машину весь прирост
  недели, включая чужой.

Готовый блок — в `~/.claude-zai/statusline-command.sh` на Mac (раздел «синхронизация между машинами»).

## Бот

- `/devices` — список машин, `/rename` — переименовать (кнопками или `/rename id Новое имя`).
- `/limits` — по каждому пулу неделя и 5 часов: кто сколько потратил, сколько осталось, когда сброс и какой нужен темп,
  чтобы выбрать лимит целиком. Есть кнопка «Обновить».
- `/history` — итоги прошлых недель.
- `/settings` — включение и выключение уведомлений.

Уведомления:
- за 24 ч, 6 ч и 1 ч до недельного сброса, если свободно ≥ 20 %, 10 % и 3 % соответственно;
- недельный лимит использован на 90 % и больше;
- недельный сброс, с итогами недели по машинам;
- за 30 мин до сброса 5-часового окна, если в нём свободно ≥ 40 %.

## Ограничения точности

- Доля машины зависит от её трат по ценам API. Если машины работают на разных моделях, этот вес не совсем
  совпадает с тем, как Anthropic списывает лимит, но для одной и той же модели пропорция верная.
- Если машина и claude.ai тратят одновременно, web-расход достаётся машине: отличить их нечем.
- Траты сессии после её последнего отчёта (≤ 5 с) теряются.
